3) The 3 candidates that did NOT make it — also real, shown for transparency

  • Chronic pain / tissue healing claim — NIH source found, but its real content discussed acute-vs-chronic pain definitions generally, not the specific claim. Judge: not supported.
  • Same knee-valgus claim, 2 more PubMed URLs — both real, correct PMIDs from web search, but fetching pubmed.ncbi.nlm.nih.gov abstract pages returned a cookie-consent page instead of the abstract. Judge correctly refused to treat a cookie notice as evidence.
A real, specific bug found by this exact run — fixed 2026-08-29: every pubmed.ncbi.nlm.nih.gov/<pmid>/ URL surfaced by web search failed verification because fetching it returns a cookie-consent interstitial, not the abstract — on THIS post and on the other pending post run at the same time (a full run against “Why stretching and massage are not fixing your pain” found 0 citations for exactly this reason, 6/6 real PubMed candidates rejected as unreadable). The accepted citation above worked because it happened to be a pmc.ncbi.nlm.nih.gov full-text URL, which fetches cleanly. Fix shipped: when a candidate's URL matches pubmed.ncbi.nlm.nih.gov/(\d+), re-fetch its abstract via the same E-utilities efetch call searchPubMed already uses, instead of scraping the HTML page — see api/_lib/citations/pubmedClient.js's fetchPubmedAbstractByPmid, wired into verify.js's fetchCandidateContent. Separately fixed: retrieved web URLs carried a ?utm_source=openai tracking param, now stripped in webSearchClient.js before a citation URL is ever stored or shown.
