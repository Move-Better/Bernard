Design notes (both open questions resolved 2026-08-28)

  • Placement: inside ApprovalPanel, gated on piece.platform === 'blog' (covers series parts too — they're platform:'blog' with series_id set). Shown regardless of draft/approved status, per the spec ("before Approve/Schedule/Publish").
  • Tier chips map 1:1 to allowlist.js's CITATION_SOURCE_TIERS — Peer-reviewed / Major institution / Professional guidelines / Health-ed. Not decorative.
  • Confidence bar is the judge's real confidence (0–1), never a fabricated/rounded display value beyond formatting as a percentage. Resolved: Q confirmed this is useful, not noise — kept as-is.
  • Rejected rows stay visible (struck through, muted) rather than disappearing — the spec calls this an audit trail, and a reviewer should be able to see "yes, I already looked at that one and said no."
  • Resolved — link placement: both. Inline in the body at the exact sentence, AND in the "Further reading" footer — Q: "the redundancy adds clarity." Approving still can't corrupt hand-edited prose: inlining only happens on an exact, single-occurrence match of the source quote against the CURRENT body, re-checked live (not from enrichment time). When the quote has drifted or gone ambiguous, it degrades to footer-only for that one citation rather than guessing — the small badge above each card's action row (green check vs. amber warning) is that live check, shown to the reviewer BEFORE they approve. See .claude/blog-research-citations-spec.md's "Link placement" section for the full design.
